## Beispiel aus der Praxis

Ein Einsatz von n8n aus Ozan Orhans Arbeit ist der [Recruiting Jobs Sync](/projekte/recruiting-jobs-sync/). Die Quelle ist eine Karriereseite ohne API. Ein n8n-Workflow mit Zeitplan-Trigger läuft täglich, sammelt die Links zu den Stellenanzeigen ein und erzeugt aus jedem Pfad einen stabilen Schlüssel.

Für jede Anzeige entfernt ein Code-Schritt zuerst Skripte, Styles und Markup. Danach zerlegt ein Sprachmodell den Text schema-gebunden in Felder, und ein Upsert schreibt das Ergebnis über den Schlüssel in den Datenspeicher. Stellen, die in einem Lauf nicht mehr auftauchen, setzt der Workflow auf inaktiv, statt sie zu löschen.

Ein zweites Beispiel ist die [Leistungsnachweis-Automation](/projekte/leistungsnachweis-automation/). Dort startet eine Reaktion auf eine Slack-Nachricht den monatlichen Lauf. Der Workflow lädt Zeiteinträge aus der Toggl API, bereitet sie je Kunde auf, erzeugt Tabellen und Dokumente, legt sie in Google Drive ab und meldet den Abschluss zurück in Slack.

## Wie funktioniert n8n?

Ein n8n-Workflow ist eine Sammlung von Nodes, die einen Ablauf automatisieren (n8n Docs). Jeder Node erledigt eine Aufgabe: Daten abrufen, umwandeln, verzweigen oder an einen anderen Dienst senden.

Am Anfang steht ein Trigger-Node. Er startet den Workflow, wenn eine Bedingung eintritt, etwa ein Zeitplan, ein eingehender Webhook oder ein abgeschicktes Formular. Workflows lassen sich außerdem manuell starten oder von anderen Workflows aufrufen (n8n Docs). Danach läuft der Ablauf Node für Node und kann sich verzweigen, zusammenführen und Schleifen bilden.

Zugangsdaten für angebundene Dienste speichert n8n als Credentials, getrennt vom Workflow. Wo die vorgefertigten Nodes nicht reichen, setzt man Ausdrücke in JavaScript oder einen Code-Node ein. Jeder einzelne Lauf eines Workflows heißt Execution und lässt sich im Nachhinein mit seinen Daten einsehen.

## Ist n8n Open Source?

Nicht im engeren Sinn. n8n beschreibt seine Lizenzen als fair-code und den Code als source-available; eine klassische Open-Source-Lizenz verwendet n8n nach eigener Aussage bewusst nicht (n8n Docs). Der Quellcode liegt trotzdem öffentlich auf GitHub.

Die Sustainable Use License erlaubt Nutzung, Änderung und Weitergabe mit drei Einschränkungen (n8n Docs). Die Software darf nur für eigene interne Geschäftszwecke oder nicht kommerziell genutzt werden. Weitergeben darf man sie nur kostenlos und für nicht kommerzielle Zwecke. Lizenz- und Urheberhinweise dürfen nicht entfernt werden.

Quellcode-Dateien mit `.ee.` im Namen stehen unter der separaten n8n Enterprise License. Praktisch heißt das: Ein Unternehmen darf n8n intern selbst hosten und für eigene Abläufe nutzen. Wer n8n Kunden so anbietet, dass diese eigene Konten verbinden und Workflows bauen, braucht laut n8n eine eigene kommerzielle Vereinbarung.

## n8n Cloud oder selbst hosten: Was ist der Unterschied?

| Merkmal | n8n Cloud | Selbst gehostet |
| --- | --- | --- |
| Betrieb | n8n hostet, aktualisiert und skaliert | Eigene Infrastruktur und Wartung |
| Einstieg | Ohne Installation, mit kostenloser Testphase | Installation per Docker, npm oder über einen Cloud-Anbieter |
| Kosten | Kostenpflichtige Pläne | Community Edition kostenlos, Business und Enterprise kostenpflichtig |
| Kontrolle | Begrenzt auf die angebotenen Optionen | Volle Kontrolle über Umgebung und Konfiguration |

Die Gegenüberstellung folgt der Entscheidungshilfe in der n8n-Dokumentation. Einige Funktionen wie SSO, Umgebungen, Projekte und Versionskontrolle mit Git setzen auch beim Selbsthosten einen bezahlten Plan voraus (n8n Docs).

Die Cloud-Pläne rechnen nach monatlichen Workflow-Executions ab, unabhängig davon, wie viele Schritte ein Workflow hat (n8n Preisseite). Konkrete Preise, Grenzen und den Funktionsumfang je Plan nennt die [Preisseite von n8n](https://n8n.io/pricing/) (Stand: Oktober 2026).

## Wie nutzt man n8n mit KI und MCP?

Für KI-Schritte bietet n8n den AI-Agent-Node, der innerhalb eines Workflows läuft und mit Chat-Modell, Werkzeugen und Memory erweitert wird. Daneben gibt es n8n Agents als eigenständige Objekte im Projekt, die sich im Preview-Status befinden (n8n Docs). Wann welcher Weg passt, vergleicht der Beitrag [n8n Agents vs. AI-Agent-Node](/blog/n8n-agents-vs-ai-agent-node/).

Für das [Model Context Protocol](/glossar/mcp-model-context-protocol/) gibt es zwei Richtungen. Mit dem MCP Server Trigger wird ein Workflow zum MCP-Server, dessen angehängte Werkzeuge Clients wie Claude aufrufen können. Mit dem MCP Client Tool nutzt ein AI-Agent-Node die Werkzeuge eines externen MCP-Servers (n8n Docs). Die Einrichtung beschreibt die Anleitung [n8n MCP Server erstellen](/blog/mcp-server-mit-n8n-erstellen/).

Ein Beispiel für die Server-Richtung ist die [Wissensbasis mit RAG und MCP](/projekte/wissensbasis-rag-mcp/): Ein n8n-Workflow stellt die Suche in internen Dokumenten als nur lesendes Werkzeug für beliebige Agenten bereit. Die Suche selbst läuft über eine [Vektordatenbank](/glossar/vektordatenbank/) in PostgreSQL.

## Welche Fehler gibt es beim Einsatz von n8n?

**Kein Fehler-Workflow.** Ohne Benachrichtigung fällt ein fehlgeschlagener Lauf erst auf, wenn jemand das Ergebnis vermisst. n8n erlaubt pro Workflow einen Fehler-Workflow, der mit dem Error Trigger beginnt und zum Beispiel eine Slack- oder E-Mail-Meldung verschickt (n8n Docs).

**Test-URL und Produktions-URL verwechselt.** Der MCP Server Trigger hat eine Test-URL für die Entwicklung und eine Produktions-URL, die n8n erst registriert, wenn der Workflow veröffentlicht ist (n8n Docs). Wer nur speichert, bekommt auf der Produktions-URL keine Antwort.

**Zu weite Credentials.** Ein API-Schlüssel mit Vollzugriff in einem Workflow, der nur lesen muss, vergrößert den Schaden bei Fehlern. Besser sind eigene Credentials pro Zweck mit minimalen Rechten.

**Nicht wiederholbare Abläufe.** Läuft ein Workflow nach einem Fehler erneut, darf er keine Duplikate erzeugen. Der Recruiting Jobs Sync löst das über einen Upsert mit einem stabilen Schlüssel aus der URL.

**Lizenz nicht geprüft.** Wer n8n in ein eigenes Produkt für Kunden einbauen will, sollte vorher die Sustainable Use License lesen, weil diese Nutzung ohne gesonderte Vereinbarung nicht erlaubt ist.
